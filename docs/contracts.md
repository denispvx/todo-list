# Контракты задач

## Данные

`Task` — readonly объект `{ id: string; title: string; completed: boolean }`. ID уникален внутри списка и создаётся через `crypto.randomUUID()` до передачи action. Одинаковые названия разрешены. Порядок массива значим: новые задачи в начале, toggle не перемещает строки. Операции работают по ID.

`validateTaskTitle(raw)` выполняет `trim()` и возвращает `{ ok: true, title }` либо `{ ok: false, error: 'empty' | 'too-long' }`. Максимум — 200 единиц UTF-16 после trim, как у JavaScript `length`. Форма ограничивает исходный ввод HTML `maxLength=200`; это более строгая граница для пробелов на краях. Текст внутри строки не меняется. TypeScript не проверяет внешние JSON-данные, поэтому storage проверяет их структуру в runtime.

## Интерфейс

| Компонент | Вход | Обязанность |
| --- | --- | --- |
| TaskForm | `onAdd(rawTitle): AddTaskResult` | Передаёт исходную строку; очищает поле только при `ok: true`, показывает ошибку иначе |
| TaskItem | task, onToggle(id), onRemove(id), optional onUpdate(id, rawTitle) | Checkbox, удаление и редактор с возвратом фокуса |
| TaskList | readonly tasks, onToggle(id), onRemove(id), optional onUpdate | Пустое состояние и фокус после удаления строки |
| StorageNotice | status, onReplace(), optional replacementFailed | Предупреждение; явная замена только после invalid, видимая ошибка при отказе |
| TaskFilters | tasks, value, onChange | Фильтры и фактические счётчики без изменения данных |
| BatchPanel | initialText, onSubmit(text), onClose | Предпросмотр, валидация всего пакета и сохранение черновика при отказе |
| UndoNotice | title, onUndo, onDismiss | Последнее удаление без автоматического срока исчезновения |

Обработчик добавления всегда самостоятельно вызывает `validateTaskTitle`: UI не является доверенной границей. После успешного добавления фокус остаётся в поле. TaskList отвечает за перевод фокуса после удаления: следующий checkbox, предыдущий, затем `#task-title` при пустом списке. Форма держит этот стабильный ID. Компоненты не читают storage. Ошибки отображаются текстом, а пользовательские строки не трактуются как HTML.

## Состояние и сохранение

`TaskAction`: add(task), add-many(tasks), update(id, title), toggle(id), remove(id), restore(task, index). Reducer чистый, не генерирует ID и не выполняет I/O. Неизвестный ID не меняет состояние. `TasksController` объединяет readonly tasks, storageStatus, addTask, addTasks, updateTask, toggleTask, removeTask, lastRemovedTask, undoRemoval, dismissUndo и replaceSavedTasks.

`StoredTasks`: `{ version: 1, tasks: Task[] }`; ключ `todo-list:tasks:v1`.

| Результат load | Значение | Разрешена автоматическая запись |
| --- | --- | --- |
| ready(tasks) | Валидный список; отсутствующий ключ даёт [] | После реального изменения, не при mount |
| invalid | JSON/схема/версия/уникальность ID невалидны | После явной успешной замены текущим списком |
| unavailable | Прочитать существующие данные не удалось | Нет, до reload и новой успешной загрузки |

`save` возвращает `{ ok: true } | { ok: false }`. Ошибка записи сохраняет список в памяти и даёт `storageStatus: 'write-error'`. Успешная следующая запись снимает ошибку. `replaceSavedTasks` применим только к invalid; иначе возвращает `ok: false`. Он заменяет только ключ приложения текущим списком; при неуспехе блокировка остаётся. App показывает отказ восстановления через replacementFailed и после успеха возвращает фокус в поле ввода, поскольку кнопка восстановления исчезает.

Валидация envelope проверяет типы, version, непустые ID, их уникальность, канонические title (trim не меняет строку, длина 1–200) и boolean completed. Весь I/O защищён try/catch, чужие ключи не затрагиваются.

Инициализация только читает данные. После пользовательского действия hook вычисляет следующий массив чистым reducer и синхронно сохраняет его до обновления React-состояния, если запись разрешена. Запись не выполняется внутри reducer, initializer или state updater. Последнее состояние в ref позволяет корректно обработать несколько действий до следующего рендера. Эта схема не требует эффекта сохранения и не пишет при первом mount, включая StrictMode. Многовкладочная работа: последняя успешная запись побеждает, синхронизация не обещается.

## Пакетное добавление

`parseBatchDraft(text)` разбивает CRLF/CR/LF, убирает распространённые маркеры списков и checkbox Markdown. Пустые и состоящие только из маркера строки игнорируются. `BatchPreview` содержит lines (не более 50), total, tooMany и valid. Номер строки относится к исходному тексту. Превышение 200 единиц UTF-16 в любой задаче или 50 задач блокирует весь пакет; лишние строки не обрезаются молча. Одинаковые названия разрешены, все новые задачи незавершённые.

`addTasks(titles): BatchAddResult` повторно проверяет весь массив до создания ID. Успешный пакет добавляется перед прежними задачами в порядке исходных строк: один action и одна запись storage. Некорректный пакет не добавляет ни одной задачи.

## Редактирование и фильтры

`updateTask(id, rawTitle): AddTaskResult` проверяет название той же функцией, что и добавление. Сохраняются ID, completed и порядок. Одинаковое название после trim и неизвестный ID дают no-op без записи. Enter сохраняет, Escape отменяет; фокус возвращается на карандаш. Отказ валидации оставляет черновик и фокус в редакторе. Ошибка storage обрабатывается общим предупреждением, изменение остаётся в памяти.

Фильтр живёт только в UI. Он не меняет массив, прогресс, storage или доступные фокусу задачи. Добавление и отмена удаления переключают отображение на «Все», чтобы результат был видимым. Если toggle или удаление убирает последнюю видимую строку, фокус возвращается в поле ввода. Отсутствие задач в фильтре отличается от пустого списка.

## Отмена удаления

Hook хранит одну запись в памяти: Task, исходный индекс и ID соседей. Реальное следующее удаление заменяет историю; добавление, редактирование и toggle её сохраняют. `undoRemoval(): boolean` восстанавливает прежний ID/title/completed перед сохранившимся следующим соседом, иначе после предыдущего, иначе по ограниченному исходному индексу. Если удалённая задача изначально была единственной, она возвращается после задач, добавленных позднее. Восстановление выполняет одну запись и очищает историю. `dismissUndo()` очищает только метаданные без записи задач.

Уведомление не имеет автоматического таймера. Reload очищает историю отмены. Ctrl/⌘ Z обрабатывается вне текстовых полей и открытых экранов пакетного ввода/фокуса; нативная отмена ввода сохраняется. После восстановления фокус переходит на checkbox возвращённой задачи.

## Режим фокуса

Отдельный ключ `todo-list:focus:v1`: `{ version: 1, taskId, remainingMs, endsAt }`. Схема задач остаётся v1. Начальная длительность — 25 минут; автозапуска нет. Время вычисляется по абсолютному `endsAt`, поэтому фоновые задержки interval не накапливают погрешность. Interval обновляет отображение, а запись происходит только при select/start/pause/reset/clear. Достижение нуля не завершает задачу автоматически.

Состояние таймера проверяется при чтении: версия, ID, конечные числа, диапазон remainingMs и разумная будущая граница endsAt. Некорректное значение игнорируется без записи при mount. Ошибка чтения блокирует запись таймера до reload; ошибка записи оставляет сессию в памяти с отдельным предупреждением. Чужие ключи не затрагиваются.

Экран — нативный modal dialog, фон недоступен для взаимодействия. Escape/закрытие возвращает фокус на кнопку входа или поле ввода, если все задачи завершены. Закрытие не останавливает таймер. Переключение задачи сбрасывает отсчёт без автозапуска; «Готово» завершает задачу и открывает следующую. Checkbox основного списка или удаление выбранной задачи очищает соответствующую сессию. Таймер имеет `aria-live=off`, чтобы не объявлять каждую секунду.
